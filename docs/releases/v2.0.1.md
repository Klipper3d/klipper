# v2.0.1 — Native BMCU card, manual refill and workflow safety

**English** | [Português brasileiro](../pt-BR/releases/v2.0.1.md)

## Changes

- BMCU-Klipper **1.1.2**, pinned at
  `a1215523c51551cf11cf4c4aca39aa56b6565ea8`, requires BMCU firmware **1.0.4**.
  Incompatible firmware never receives motion permission through the Ender flow.
- Native [Mainsail card](../Ender3_V3_SE_Mainsail.md) for **2.19.0**: four colored
  spools, material, real channel state, guarded metadata editing and runout hints.
  It reuses the existing connection and native BMCU metadata persistence.
- Confirmed same-channel refill uses the native BMCU `RESUME` wrapper. Loading,
  35 mm purge and wiping finish before resuming the same paused print. Missing
  replacement, a cold nozzle or a failed purge leaves the print paused.
- Default wiping is six full X=-6 ↔ -3 round trips plus the final crossing at
  fixed Y=123, without additional Y motion. Existing explicit calibration is
  preserved; the installer does not silently replace custom wipe settings.
- Session, sensor, extrusion readiness and feeder-assistance checks remain
  active through the last purge increment and every wipe crossing. Redundant
  assistance-mode writes are reduced without removing waits or safety checks.
  Assistance lost at the nozzle-feed/purge boundary aborts before any rearming
  or additional extrusion, keeping a pending refill paused.
- Installation and generated rollback reuse the verified native 1.1.2 transport
  process helpers rather than the old systemd transport-unit assumption. Native
  modules, including the official panel module, are preserved.

## Upgrade and rollback

This is **not** a one-command upgrade from BMCU 1.0.6 / firmware 1.0.1.
The Ender installer requires an already ready BMCU 1.1.2 / 1.0.4 installation.
Updating the package and flashing BMCU firmware are separate maintenance jobs;
neither the host updater nor the panel installer performs them. Do not deploy
this release onto the old package/firmware combination.

For an existing Ender integration, plan a supervised maintenance window:

1. Finish/cancel printing, park all channels with the old working setup, retract
   the cutter stop and verify the shared path/entry switch are clear. Preserve
   a private full backup, the old host source, package and configuration.
2. Before updating the external package, temporarily disable only the Ender
   loader sections and their options: `bmcu_ender_integration` and
   `bmcu_measurement` (or their legacy names). Keep a verbatim private copy of
   those blocks. Preserve sensor, calibration and macro definitions. Also stop
   any custom automatic startup jobs. Restart into the native-only maintenance
   configuration; do not print or issue filament commands in this state.
3. Perform the separately reviewed BMCU firmware/package maintenance using the
   official pinned release. Preserve native settings and confirm package 1.1.2,
   firmware 1.0.4, the original device identity, parked routes and a clear switch.
   Existing helpers must belong to the standard systemd Klipper installation.
4. Restore the saved Ender loader blocks **on disk, without restarting** the old
   integration. Stage the published 2.0.1 host source separately and run its
   [integration installer](../Ender3_V3_SE_Configuracao_Validada.md#install-or-update-an-existing-integration).
   It patches the installed native callbacks and starts the matching host/modules
   together. Keep calibrated purge, temperature, feed, sensor and cutter values.
5. Install the [card separately](../Ender3_V3_SE_Mainsail.md#install-and-roll-back).
   Verify supervised load/unload, wiping and same-channel runout before a long
   multicolor print. Do not reduce purge or raise rates based on unit tests.

Host rollback preserves the complete previous host/display and restores affected
files, undoing only callback changes in current BMCU state. It does not revert
the external package or either controller's firmware. During cross-version
maintenance, the previous host/integration may no longer match the new package:
if readiness cannot be confirmed, services remain stopped. Restore the saved
native-only maintenance configuration and review the package/firmware boundary
before restarting. Do not copy old route snapshots over new physical evidence.

The card has its own validated backup/rollback. It refuses to discard later
configuration/theme changes. See the [2.0.0 notes](v2.0.0.md) for the earlier
English command migration; re-slice jobs using obsolete Portuguese commands.

## Validation and limits

Software checks cover the actual pinned refill method bodies, patched source
compilation/idempotence, native process ownership/stop using a harmless sleeping
process, virtual-SD pause/resume, failure retention, dashboard helpers and panel
archive/activation/rollback. Browser verification uses synthetic local state,
not the printer. The build includes upstream Mainsail and overlay licenses and
checksummed provenance. Physical refill acceptance, purge detachment and timing
gains remain commissioning checks, not software-test claims.

Recovery after **power loss or controller/host restart is not included** in
2.0.1. Existing recovery retains an in-memory paused print only. CR-Touch homing,
temperatures, motion limits, servo/PWM behavior and calibration are not relaxed.
