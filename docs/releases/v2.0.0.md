# v2.0.0 — English API, bilingual documentation and prepared rollback

**English** | [Português brasileiro](../pt-BR/releases/v2.0.0.md)

## Breaking change

Public integration commands, parameters, enum values, configuration keys and
status fields are English only. Known v1 configuration names and persisted
endpoint callbacks are migrated before activation. Conflicting names and
ambiguous custom templates fail for manual review; Portuguese command aliases
are not installed. **Re-slice old print jobs with the v2 Orca profile.** Stored
G-code is not silently converted, overwritten or executed by migration.

## Changes

- Complete English and Brazilian Portuguese public documentation, including
  upstream guides, READMEs, historical notes and maintained plans. English is
  canonical. Translation sources, credits, license and review policy are
  recorded in the [translation guide](../Translations.md).
- Organized stock-display menus with one owner per operation. Language changes
  immediately in **Settings → Language**; guarded **Save config** persists it
  separately and confirms the Klipper restart.
- Confirmed BMCU reset after manual removal outside printing, using
  `RESET_BMCU CONFIRM=1`. Paused failed changes retain their print map and use
  per-channel path confirmation, not a global reset. An uncertain cutter offers
  only its guarded retract recovery, not homing or jogging.
- Prepared host/display upgrade from an independent clean checkout, preserving
  the entire previous tree, calibration, installation settings, installed
  optional modules and Git remotes. Startup failure restores the previous
  host/display and affected configuration without overwriting current routes.
  Recovered-host readiness is required; otherwise services remain stopped.
- English Orca start/end/change snippets and a regenerated four-channel reload
  project. Native BMCU logical-tool resolution and transport behavior are kept.
- Existing physical cutter/homing fixes, preheat profiles, calibrations, required
  callbacks and operational macros are preserved. Only exact redundant default
  display shortcuts were removed; custom shortcuts remain.

## Upgrade and rollback

Back up first. Keep the printer idle, channels parked and entry sensor clear.
**Do not update the active checkout with `git pull` before staging the upgrade.**
Use the [prepared installer and rollback procedure](../Ender3_V3_SE_Configuracao_Validada.md#install-or-update-an-existing-integration)
from a separate clean checkout of the published tag with `--host-source`.
Unknown calibration and installation values are not replaced by defaults.

After the v2.0.0 tag is published, prepare the update from a separate clean
source checkout:

```sh
git clone --branch v2.0.0 --single-branch \
  https://github.com/bernardokcosta/ender3-v3-se-klipper-bmcu.git \
  "$HOME/klipper-v2-source"
sudo python3 "$HOME/klipper-v2-source/scripts/ender3-v3-se/install_multicolor.py" \
  --host-source "$HOME/klipper-v2-source"
```

The staged installer preserves the old checkout, installed optional modules,
calibration and integration settings. Startup failure restores the complete
previous host/display and affected configuration. The recovered host must
become ready; otherwise services stay **stopped**. Both checkouts are retained
for diagnosis. Updating Git alone does not replace optional modules in
`klippy/extras/`.

This automatic transaction is host-only: it refuses changed MCU/build inputs
or Python requirements and does not flash firmware or install dependencies.
Integration-only mode cannot restore a checkout changed separately beforehand.
Retain both private backup directories and both host trees for recovery.
Rollback reverses only recognized callback renames in current BMCU state;
it must not copy stale route state over present evidence.

## Dependencies and hardware limits

BMCU-Klipper remains **1.0.6**, BMCU firmware **1.0.1** and the slicer examples
target OrcaSlicer **2.4.2**. The mainboard target remains the verified
CR4NS200320C14 / GD32F303RET6, STM32F103-compatible build with 28 KiB bootloader
and USART1. Do not flash its binary onto STM32F401 hardware.

The implementation preserves prior physical fixes; this release does not claim
new physical v2 acceptance. Earlier physical evidence covers one assembly and a
two-color PETG print, not all revisions, materials or four-color printing.
Experimental tip forming and the optional cutter still require calibration.
No proprietary stock-display firmware or automatic PRTouch/HX711 Z-offset
firmware is included. See the [hardware guide](../Ender3_V3_SE.md).

## Publication gates

Publication requires integration, display and documentation regressions, strict
public-document checks, original whitespace validation, the target firmware
build and complete Klippy configuration test. The general Klipper workflow must
also pass for the release commit. Merge occurs only through the protected
master pull-request checks; a local candidate is not a published release.

Published binaries must identify the tagged source commit and include
`klipper.dict`, `defconfig`, `BUILD-METADATA.txt` and verified `SHA256SUMS`.
No printer deployment, movement or heating is implied by these software checks.
