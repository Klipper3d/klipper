# Comandos MCU

[English](../MCU_Commands.md) | **Português brasileiro**

Este documento fornece informações sobre os comandos do microcontrolador de baixo nível que são enviados do software "host" Klipper e processados pelo software do microcontrolador Klipper. Este documento não é uma referência oficial para esses comandos, nem é uma lista exclusiva de todos os comandos disponíveis.

Este documento pode ser útil para desenvolvedores interessados em entender os comandos de baixo nível do microcontrolador.

Consulte o documento [protocol](Protocol.md) para mais informações sobre o formato dos comandos e sua transmissão. Os comandos aqui são descritos usando sua sintaxe de estilo "printf" - para quem não está familiarizado com esse formato, observe apenas que onde uma sequência '%...' for vista ela deve ser substituída por um número inteiro real. Por exemplo, uma descrição com "count=%c" poderia ser substituída pelo texto "count=10". Observe que parâmetros considerados "enumerações" (consulte o documento de protocolo acima) recebem um valor de string que é automaticamente convertido em um valor inteiro para o microcontrolador. Isso é comum com parâmetros chamados "pin" (ou que têm o sufixo "_pin").

<a id="startup-commands"></a>
## Comandos de inicialização

Pode ser necessário realizar certas ações únicas para configurar o microcontrolador e seus periféricos. Esta seção lista comandos comuns disponíveis para esse fim. Diferentemente da maioria dos comandos do microcontrolador, esses comandos são executados assim que são recebidos e não exigem nenhuma configuração específica.

Comandos comuns de inicialização:

* `set_digital_out pin=%u value=%c` : Este comando configura imediatamente o pino informado como GPIO de saída digital e o define em nível baixo (value=0) ou em nível alto (value=1). Este comando pode ser útil para configurar o valor inicial de LEDs e para configurar o valor inicial dos pinos de micropassos do driver do motor de passo.
* `set_pwm_out pin=%u cycle_ticks=%u value=%hu` : Este comando configurará imediatamente o pino informado para usar modulação por largura de pulso (PWM) baseada em hardware com o número informado de cycle_ticks. O "cycle_ticks" é o número de tiques de relógio do MCU que cada ciclo de ligado e desligado deve durar. Um valor de cycle_ticks igual a 1 pode ser usado para solicitar o tempo de ciclo mais rápido possível. O parâmetro "value" fica entre 0 e 255, com 0 indicando estado totalmente desligado e 255 indicando estado totalmente ligado. Este comando pode ser útil para habilitar ventiladores de resfriamento da CPU e do bico.

<a id="low-level-micro-controller-configuration"></a>
## Configuração de baixo nível do microcontrolador

A maioria dos comandos no microcontrolador exige uma configuração inicial antes de poderem ser invocados com sucesso. Esta seção fornece uma visão geral do processo de configuração. Esta seção e as seções seguintes provavelmente são de interesse somente para desenvolvedores interessados nos detalhes internos do Klipper.

Quando o hospedeiro se conecta pela primeira vez ao microcontrolador, ele sempre começa obtendo um dicionário de dados (consulte [protocol](Protocol.md) para mais informações). Após obter o dicionário de dados, o hospedeiro verificará se o microcontrolador está em estado "configurado" e o configurará se não estiver. A configuração envolve as seguintes fases:

* `get_config` : O hospedeiro começa verificando se o microcontrolador já está configurado. O microcontrolador responde a este comando com uma mensagem de resposta "config". O software do microcontrolador sempre inicia em estado não configurado ao ligar. Ele permanece nesse estado até o hospedeiro concluir os processos de configuração (emitindo um comando finalize_config). Se o microcontrolador já estiver configurado a partir de uma sessão anterior (e estiver configurado com as definições desejadas), nenhuma ação adicional do hospedeiro será necessária e o processo de configuração termina com êxito.
* `allocate_oids count=%c` : Este comando é emitido para informar ao microcontrolador o número máximo de identificadores de objeto (oid) de que o hospedeiro necessita. Só é válido emitir este comando uma vez. Um oid é um identificador inteiro atribuído a cada motor de passo, a cada fim de curso e a cada pino gpio agendável. O hospedeiro determina antecipadamente o número de oids de que precisará para operar o hardware e o transmite ao microcontrolador para que ele possa alocar memória suficiente para armazenar o mapeamento de oid para objeto interno.
* `config_XXX oid=%c ...` : Por convenção, qualquer comando que comece com o prefixo "config_" cria um novo objeto do microcontrolador e atribui a ele o oid informado. Por exemplo, o comando config_digital_out configurará o pino especificado como GPIO de saída digital e criará um objeto interno que o hospedeiro pode usar para agendar alterações no GPIO informado. O parâmetro oid transmitido ao comando config é escolhido pelo hospedeiro e deve ficar entre zero e a contagem máxima fornecida no comando allocate_oids. Os comandos config só podem ser executados quando o microcontrolador não está em estado configurado (ou seja, antes de o hospedeiro enviar finalize_config) e depois que o comando allocate_oids tiver sido enviado.
* `finalize_config crc=%u` : O comando finalize_config transfere o microcontrolador de um estado não configurado para um estado configurado. O parâmetro crc transmitido ao microcontrolador é armazenado e devolvido ao hospedeiro nas mensagens de resposta "config". Por convenção, o hospedeiro calcula um CRC de 32 bits da configuração que solicitará e, no início das sessões de comunicação seguintes, verifica se o CRC armazenado no microcontrolador corresponde exatamente ao seu CRC desejado. Se o CRC não corresponder, o hospedeiro saberá que o microcontrolador não foi configurado no estado desejado pelo hospedeiro.

<a id="common-micro-controller-objects"></a>
### Objetos comuns do microcontrolador

Esta seção lista alguns comandos de configuração comumente usados.

* `config_digital_out oid=%c pin=%u value=%c default_value=%c max_duration=%u` : Este comando cria um objeto interno do microcontrolador para o 'pin' GPIO informado. O pino será configurado em modo de saída digital e definido com um valor inicial conforme especificado por 'value' (0 para baixo, 1 para alto). A criação de um objeto digital_out permite ao hospedeiro agendar atualizações de GPIO para o pino informado em horários especificados (consulte o comando queue_digital_out descrito abaixo). Se o software do microcontrolador entrar em modo de desligamento, todos os objetos digital_out configurados serão definidos como 'default_value'. O parâmetro 'max_duration' é usado para implementar uma verificação de segurança - se for diferente de zero, ele é o número máximo de tiques de relógio que o hospedeiro pode manter o GPIO informado em um valor diferente do padrão sem atualizações adicionais. Por exemplo, se o default_value for zero e o max_duration for 16000, se o hospedeiro definir o gpio com valor um, ele deverá agendar outra atualização para o pino gpio (para zero ou um) dentro de 16000 tiques de relógio. Este recurso de segurança pode ser usado com pinos de aquecedores para garantir que o hospedeiro não habilite o aquecedor e depois fique fora de linha.
* `config_pwm_out oid=%c pin=%u cycle_ticks=%u value=%hu default_value=%hu max_duration=%u` : Este comando cria um objeto interno para pinos PWM baseados em hardware que o hospedeiro pode atualizar de forma agendada. Seu uso é análogo ao de config_digital_out - consulte a descrição dos comandos 'set_pwm_out' e 'config_digital_out' para a descrição dos parâmetros.
* `config_analog_in oid=%c pin=%u` : Este comando é usado para configurar um pino em modo de amostragem de entrada analógica. Uma vez configurado, o pino pode ser amostrado em intervalo regular usando o comando query_analog_in (consulte abaixo).
* `config_stepper oid=%c step_pin=%c dir_pin=%c invert_step=%c step_pulse_ticks=%u` : Este comando cria um objeto interno de motor de passo. Os parâmetros 'step_pin' e 'dir_pin' especificam os pinos de passo e de direção, respectivamente; este comando os configurará em modo de saída digital. O parâmetro 'invert_step' especifica se um passo ocorre na borda de subida (invert_step=0) ou na borda de descida (invert_step=1). O parâmetro 'step_pulse_ticks' especifica a duração mínima do pulso de passo. Se o mcu exportar a constante 'STEPPER_BOTH_EDGE=1', definir step_pulse_ticks=0 e invert_step=-1 configurará o passo tanto nas bordas de subida quanto de descida do pino de passo.
* `config_endstop oid=%c pin=%c pull_up=%c stepper_count=%c` : Este comando cria um objeto interno de "endstop". Ele é usado para especificar os pinos de fim de curso e para habilitar operações de "homing" (consulte o comando endstop_home abaixo). O comando configurará o pino especificado em modo de entrada digital. O parâmetro 'pull_up' determina se resistores de pullup de hardware do pino (se disponíveis) serão habilitados. O parâmetro 'stepper_count' especifica o número máximo de motores de passo que este fim de curso pode precisar deter durante uma operação de homing (consulte endstop_home abaixo).
* `config_spi oid=%c bus=%u pin=%u mode=%u rate=%u shutdown_msg=%*s` : Este comando cria um objeto SPI interno. Ele é usado com os comandos spi_transfer e spi_send (consulte abaixo). O "bus" identifica o barramento SPI a usar (se o microcontrolador tiver mais de um barramento SPI disponível). O "pin" especifica o pino de seleção de chip (CS) do dispositivo. O "mode" é o modo SPI (deve ficar entre 0 e 3). O parâmetro "rate" especifica a taxa do barramento SPI (em ciclos por segundo). Por fim, o "shutdown_msg" é um comando SPI a enviar ao dispositivo informado caso o microcontrolador entre em estado de desligamento.
* `config_spi_without_cs oid=%c bus=%u mode=%u rate=%u shutdown_msg=%*s` : Este comando é semelhante a config_spi, mas sem definição de pino CS. Ele é útil para dispositivos SPI que não possuem linha de seleção de chip.

<a id="common-commands"></a>
## Comandos comuns

Esta seção lista alguns comandos de tempo de execução comumente usados. Ela provavelmente é de interesse somente para desenvolvedores que buscam entender o Klipper.

* `set_digital_out_pwm_cycle oid=%c cycle_ticks=%u` : Este comando configura um pino de saída digital (conforme criado por config_digital_out) para usar "PWM por software". O 'cycle_ticks' é o número de tiques de relógio do ciclo PWM. Como o chaveamento da saída é implementado no software do microcontrolador, recomenda-se que 'cycle_ticks' corresponda a um tempo de 10ms ou maior.
* `queue_digital_out oid=%c clock=%u on_ticks=%u` : Este comando agendará uma alteração em um pino GPIO de saída digital no horário de relógio informado. Para usar este comando, um comando 'config_digital_out' com o mesmo parâmetro 'oid' deve ter sido emitido durante a configuração do microcontrolador. Se 'set_digital_out_pwm_cycle' tiver sido chamado, 'on_ticks' é a duração ligado (em tiques de relógio) do ciclo pwm. Caso contrário, 'on_ticks' deve ser 0 (para tensão baixa) ou 1 (para tensão alta).
* `queue_pwm_out oid=%c clock=%u value=%hu` : Agenda uma alteração em um pino de saída PWM de hardware. Consulte os comandos 'queue_digital_out' e 'config_pwm_out' para mais informações.
* `query_analog_in oid=%c clock=%u sample_ticks=%u sample_count=%c rest_ticks=%u min_value=%hu max_value=%hu` : Este comando configura uma agenda recorrente de amostras de entrada analógica. Para usar este comando, um comando 'config_analog_in' com o mesmo parâmetro 'oid' deve ter sido emitido durante a configuração do microcontrolador. As amostras começarão no tempo 'clock', ele relatará o valor obtido a cada 'rest_ticks' tiques de relógio, fará sobreamostragem 'sample_count' vezes e pausará 'sample_ticks' tiques de relógio entre amostras de sobreamostragem. Os parâmetros 'min_value' e 'max_value' implementam um recurso de segurança - o software do microcontrolador verificará se o valor amostrado (após qualquer sobreamostragem) está sempre entre o intervalo fornecido. Isso se destina ao uso com pinos ligados a termistores que controlam aquecedores - pode ser usado para verificar se um aquecedor está dentro de um intervalo de temperatura.
* `get_clock` : Este comando faz o microcontrolador gerar uma mensagem de resposta "clock". O hospedeiro envia este comando uma vez por segundo para obter o valor do relógio do microcontrolador e para estimar a deriva entre os relógios do hospedeiro e do microcontrolador. Ele permite ao hospedeiro estimar com precisão o relógio do microcontrolador.

<a id="stepper-commands"></a>
### Comandos de motor de passo

* `queue_step oid=%c interval=%u count=%hu add=%hi` : Este comando agenda 'count' passos para o motor de passo informado, com 'interval' tiques de relógio entre cada passo. O primeiro passo ocorrerá 'interval' tiques de relógio após o último passo agendado para o motor de passo informado. Se 'add' for diferente de zero, o intervalo será ajustado em 'add' após cada passo. Este comando acrescenta a sequência interval/count/add informada a uma fila por motor de passo. Pode haver centenas dessas sequências na fila durante a operação normal. Novas sequências são acrescentadas ao fim da fila e, à medida que cada sequência conclui seu número 'count' de passos, ela é removida do início da fila. Este sistema permite ao microcontrolador enfileirar potencialmente centenas de milhares de passos - todos com horários de agendamento confiáveis e previsíveis.
* `set_next_step_dir oid=%c dir=%c` : Este comando especifica o valor do dir_pin que o próximo comando queue_step usará.
* `reset_step_clock oid=%c clock=%u` : Normalmente, a temporização de passos é relativa ao último passo de um determinado motor de passo. Este comando redefine o relógio para que o próximo passo seja relativo ao tempo 'clock' fornecido. O hospedeiro normalmente só envia este comando no início de uma impressão.
* `stepper_get_position oid=%c` : Este comando faz o microcontrolador gerar uma mensagem de resposta "stepper_position" com a posição atual do motor de passo. A posição é o número total de passos gerados com dir=1 menos o número total de passos gerados com dir=0.
* `endstop_home oid=%c clock=%u sample_ticks=%u sample_count=%c rest_ticks=%u pin_value=%c` : Este comando é usado durante operações de "homing" do motor de passo. Para usar este comando, um comando 'config_endstop' com o mesmo parâmetro 'oid' deve ter sido emitido durante a configuração do microcontrolador. Quando este comando é invocado, o microcontrolador amostrará o pino de fim de curso a cada 'rest_ticks' tiques de relógio e verificará se ele tem valor igual a 'pin_value'. Se o valor corresponder (e continuar correspondendo por 'sample_count' amostras adicionais espaçadas por 'sample_ticks'), a fila de movimento do motor de passo associado será apagada e o motor de passo parará imediatamente. O hospedeiro usa este comando para implementar o homing - o hospedeiro instrui o fim de curso a amostrar à espera do acionamento do fim de curso e então emite uma série de comandos queue_step para mover um motor de passo em direção ao fim de curso. Quando o motor de passo atinge o fim de curso, o acionamento será detectado, o movimento será detido e o hospedeiro será notificado.

<a id="move-queue"></a>
### Fila de movimentos

Cada comando queue_step utiliza uma entrada na "move queue" do microcontrolador. Essa fila é alocada quando recebe o comando "finalize_config", e informa o número de entradas de fila disponíveis nas mensagens de resposta "config".

É responsabilidade do hospedeiro garantir que haja espaço disponível na fila antes de enviar um comando queue_step. O hospedeiro faz isso calculando quando cada comando queue_step é concluído e agendando novos comandos queue_step de acordo.

<a id="spi-commands"></a>
### Comandos SPI

* `spi_transfer oid=%c data=%*s` : Este comando faz o microcontrolador enviar 'data' para o dispositivo spi especificado por 'oid' e gera uma mensagem de resposta "spi_transfer_response" com os dados retornados durante a transmissão.
* `spi_send oid=%c data=%*s` : Este comando é semelhante a "spi_transfer", mas não gera uma mensagem "spi_transfer_response".
