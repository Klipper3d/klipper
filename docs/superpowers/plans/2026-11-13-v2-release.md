# v2.0.0 Implementation Plan

**English** | [Português brasileiro](../../pt-BR/superpowers/plans/2026-11-13-v2-release.md)

> Execute task-by-task. Parallel agents may analyze/review but must not change
> shared implementation files. The main agent owns integration and final review.

**Goal:** release an English-only public command interface, safely migrate
existing installations and provide complete EN/PT-BR public documentation.

**Architecture:** reuse the existing installer, native patch boundaries and
regression benches; migrate known legacy identifiers before activating files.
Maintain English canonical documentation and explicit Portuguese counterparts.

**Tech stack:** Python, Klipper/Jinja G-code macros, unittest, GitHub Actions,
Markdown, OpenSSH only for separately authorized deployment.

**Spec:** `../specs/2026-11-13-v2-release.md`

## Global constraints

- Do not expose Portuguese command aliases in v2; re-slice old jobs.
- Preserve physical values, calibrations, device IDs and user work.
- No movement/heating/route reconciliation during upgrade or validation.
- No private documents or credentials in Git, translations or artifacts.
- Do not bypass master protection or publish an incomplete v2.
- Keep BMCU-Klipper 1.0.6 and firmware 1.0.1 unless a verified need changes this.

## Review focus

- Old installed callbacks/native patches must migrate together with macros.

- Failed/partial migration must restore all active files; reruns are idempotent.
- Language-pair coverage must not mistake English fallback for Portuguese.
- Release assets and translated examples must reference the tested English API.

## Implementation checkpoint — not release approval

- The English command/configuration migration, display calls and Orca/3MF
  artifacts are implemented locally, with no commit, push or printer deployment.
  `VERSION` still identifies the published v1 release.
- Regression evidence: 226 integration tests and 57 display tests passed locally.
  These are simulated tests, not physical acceptance of the v2 release.
- Migration rejects old/new name collisions across includes and within command
  arguments. Same-name Klipper overrides, calibration, comments and unknown
  settings are retained. Cycles and external includes requiring migration fail
  before activation.
- The installer re-reads state after stopping Klipper. Rollback changes only
  recognized callbacks in the current state; it must not restore stale routes.
  A changed transport daemon is stopped before replacement and started before
  Klipper. Failed installation and generated rollback leave services stopped.
- **Release blocker:** complete host/display version rollback is not implemented.
  Restoring integration files does not restore a checkout changed separately.
  Do not start services with mixed host/display/configuration versions.
- BMCU 1.0.6 deliberately disables runout handling for managed sensors during
  callbacks. Preserve this native contract; disabled runout handling is not
  proof that the physical switch reading is invalid or that its path is clear.
- **Release blockers:** complete public EN/PT-BR documentation, remaining English
  runtime diagnostics/status fields, migration review and release validation.
  Dormant configs, alternate state files and arbitrary custom templates require
  review; tests do not establish compatibility for every personal macro.
- The local EN→PT translation model was evaluated but not accepted as final
  documentation: the sample mistranslated a homing safety instruction. Do not
  bulk-publish its output or count English fallback as completed translation.
- The original complete whitespace checker passed on a public LF export,
  including new files. The GD32F303 target compiled there; the display protocol
  dictionary assertions and complete Klippy configuration test also passed.
  This unversioned local build is not a release artifact. External review is a
  separate gate and does not remove the documented release blockers.
- External review identified cross-include option collisions and unmigrated
  inline `gcode:` bodies. Both received failing regressions and local fixes;
  the real Klipper config parser and command dispatcher cover these cases.
  This checkpoint is not approval to deploy or publish the unfinished release.

### Final-review correction

The expanded external final review found a bypass in unsupported custom Jinja
status references: dotted lookups and chained aliases could escape migration
or silently disable legacy diagnostic conditions. Regression tests reproduced
the original output using Klipper's actual template renderer, then verified
that those unsupported forms fail for manual review before active files change.
Direct supported bracket lookups remain idempotent; unrelated private strings
and existing calibrated values are retained. The correction strengthens the
existing conservative rejection boundary, without adding a second migration
path or rewriting private diagnostic literals.

Post-correction validation passed 253 integration, 70 display and 13 checker
tests, strict documentation checks (75 pairs, zero errors), public LF whitespace,
target build and complete target configuration validation. The final-review
finding is corrected; protected PR/CI and artifact publication are still gates.
